RugFreePump publishes its Anchor IDL and TypeScript types as the definitive, machine-readable specification of its public on-chain interface.

* **Anchor IDL**: Defines the complete program structure, including instructions, account layouts, arguments, events, custom errors, and defined types.
* **TypeScript Types**: Provides strongly-typed representations of the IDL components for safe, predictable client-side integration.

RugFreePump maintains strict parity across all deployments. Because the program interface is identical across Devnet and Mainnet, the published IDL and types serve as a unified spec rather than cluster-specific variants.

## Published Artifacts

The current integration artifacts are:

| Artifact             | Description                                         |
| :------------------- | :-------------------------------------------------- |
| `rug_free_pump.json` | Published Anchor IDL for the RugFreePump program    |
| `rug_free_pump.ts`   | Generated TypeScript type representation of the IDL |

## Supported Deployments

RugFreePump maintains both Devnet and Mainnet deployments of the protocol.

The deployments are maintained against the same program interface. When the protocol implementation is updated, the corresponding program changes are applied across the supported clusters so developers can test against the same interface intended for production use.

| Deployment  | Solana Cluster | Program ID                                     |
| :---------- | :------------- | :--------------------------------------------- |
| **Devnet**  | `devnet`       | `9hpBPEiywp7FPAq5uP253eAZzdJ1Cpd36L5RAYuc9xSw` |

The program ID shown for Mainnet represents the currently documented deployment value. If the production deployment uses a different program ID, the Mainnet address will be updated independently without requiring a separate IDL or TypeScript artifact when the program interface remains unchanged.

## Interface Synchronization

The published IDL and generated TypeScript types are maintained together with the RugFreePump program interface.

Interface changes that affect the published artifacts may include changes such as:

* Instruction definitions
* Instruction arguments
* Account structures
* Account relationships
* Events
* Defined types

When such changes are introduced, the published IDL and generated TypeScript types are updated to reflect the new program interface.

Devnet and Mainnet are kept synchronized with the corresponding program interface so developers can use Devnet to test against the same protocol interface used by the production deployment.

A change to the program address alone does not constitute an interface change and does not require a separate set of IDL or TypeScript artifacts.

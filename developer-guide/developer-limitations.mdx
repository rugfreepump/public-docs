---
title: "Developer limitations"
description: "Understand the current scope and boundaries of the RugFreePump public developer interface."
---

The RugFreePump public developer interface is the **RugFreePump Solana program** and the on-chain accounts, instructions, events, PDAs, and external program accounts required by that interface.

The RugFreePump hosted application and internal backend infrastructure are not required dependencies for direct protocol integration.

## No public off-chain SDK

RugFreePump does not currently provide an official off-chain SDK.

Direct integrations can interact with the on-chain program using standard Solana tooling and the published [Anchor IDL & Types](./anchor-idl-and-types/usage).

No separate RugFreePump SDK is required to access the public on-chain interface.

## No public developer HTTP API

RugFreePump does not currently provide a dedicated public developer HTTP API for protocol interaction.

The hosted application may use backend services for indexing, transaction preparation, metadata processing, analytics, and other application functionality. These services are internal application infrastructure and are not part of the public protocol interface.

Direct protocol integrations should treat Solana and the deployed RugFreePump program as the authoritative execution and state boundary.

## No managed developer infrastructure

RugFreePump does not currently provide a managed developer platform for:

* Developer API keys
* Hosted transaction relaying
* Managed RPC access
* Hosted protocol indexing
* Dedicated quote services
* Managed transaction infrastructure

Developers integrating directly with the protocol are responsible for the infrastructure required by their own application.

## On-chain interface is the compatibility boundary

The public compatibility boundary is the deployed RugFreePump program and its published interface.

The following are part of that interface where applicable:

* Program ID
* Instructions
* Instruction arguments
* Account requirements
* PDA derivations
* Program account state
* Events
* Errors
* Required external program accounts
* Integer-scaled protocol values

The published [Anchor IDL & Types](./anchor-idl-and-types) represent the current documented program interface.

Internal application services are not part of this compatibility boundary.

## Internal infrastructure is not a public interface

RugFreePump's internal application infrastructure may change independently of the on-chain program.

Developers should not depend on undocumented or internal implementation details such as:

* Backend classes
* Internal database schemas
* Internal HTTP endpoints
* Internal WebSocket topics
* Internal transaction-builder functions
* Internal RPC configuration
* Internal metadata-processing behavior

A change to internal application infrastructure does not necessarily represent a change to the public on-chain interface.

## Deployment-specific configuration

RugFreePump maintains separate Solana deployments for Devnet and Mainnet.

Program IDs, cluster configuration, and certain external accounts are deployment-specific and must be treated accordingly.

The current published deployments are documented in [Anchor IDL & Types](./anchor-idl-and-types/usage).

External dependencies such as the Pyth SOL/USD price account and other required program accounts must also satisfy the requirements of the target deployment and instruction.

Devnet configuration must not be assumed to apply to Mainnet.

## Protocol state is authoritative on-chain

Off-chain indexes, caches, APIs, and application state may provide supporting information, but they are not the authoritative source of RugFreePump protocol state.

The deployed on-chain program and resulting Solana account state determine whether an operation is valid and what state was committed.

Applications should therefore treat cached or indexed information as secondary to the corresponding on-chain state.

## Transaction execution is external to RugFreePump infrastructure

RugFreePump does not provide a managed transaction execution service for third-party applications.

Integrators are responsible for their own:

* Solana RPC access
* Wallet and signing infrastructure
* Transaction construction
* Transaction submission
* Confirmation handling
* Retry and blockhash management
* Application-level transaction state

These responsibilities remain with the integrating application rather than the RugFreePump hosted application.

## CPI availability

The public RugFreePump Anchor instructions are CPI-compatible and can be invoked by other Solana programs when their required account, signer, authority, and state conditions are satisfied.

RugFreePump does not currently provide a maintained official CPI wrapper or Rust integration crate.

A dedicated CPI wrapper and Rust integration crate are planned as future developer tooling.

## No guarantee of internal-service compatibility

The RugFreePump application and its supporting services may evolve without preserving compatibility with undocumented internal interfaces.

Integrations should therefore be built against the published on-chain interface rather than against implementation details discovered from the hosted application.

## Interface changes

RugFreePump does not intentionally introduce breaking changes to its public on-chain interface.

However, exceptional protocol upgrades may modify instructions, arguments, accounts, events, errors, or defined types.

When such a change affects the published interface, the corresponding IDL and generated TypeScript types are updated and the [Anchor IDL & Types](./anchor-idl-and-types/usage) page receives an updated **Last Updated** date.

Developers should use the currently published artifacts rather than assuming that an older local copy remains compatible indefinitely.

## Future developer tooling

RugFreePump may introduce additional official developer tooling over time, including:

* CPI wrapper
* Rust integration crate

Future tooling does not change the current integration boundary. Unless explicitly documented as a public developer product, RugFreePump off-chain services remain internal application infrastructure.

## Scope of developer support

The Developer Guide documents the public RugFreePump on-chain interface and its documented integration requirements.

Integrators remain responsible for their own application architecture, infrastructure, wallets, RPC providers, indexing, monitoring, transaction handling, and other third-party dependencies.

The RugFreePump public integration boundary remains the deployed on-chain program and its published interface.

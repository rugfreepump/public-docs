---
title: "Buy"
description: "Integrate with the protocol's buy instruction to purchase tokens from an active bonding-curve sale."
---

The `buy` instruction purchases tokens from an active RugFreePump bonding-curve sale using SOL.

The instruction accepts a gross SOL amount, deducts the configured protocol fee, denominates the remaining SOL contribution in USD-equivalent terms using a validated Pyth SOL/USD price feed, calculates the corresponding token amount using the bonding curve pricing model, and transfers the tokens to the buyer.

### Instruction Signature

```rust
pub fn buy(
    ctx: Context<Buy>,
    lamports_amount: u64,
    expected_total_raised_usd_e2: u64,
    expected_total_sold_tokens_e6: u64,
    slippage_bps: u16,
) -> Result<()>
```

## Execution Requirements

The `buy` instruction can execute only when the sale satisfies the required protocol state and purchase conditions.

### Sale State

At execution time:

* Platform maintenance mode must be disabled.
* `is_sale_active` must be `true`.
* `is_sale_finalized` must be `false`.
* `is_finalized_sale_canceled` must be `false`.
* The current time must be before `sale_expires_at`.

If the sale expiration time has been reached, the program marks the sale inactive and rejects the purchase.

### Purchase Amount

`lamports_amount` must be greater than zero and the buyer must have sufficient SOL to cover the submitted amount.

The configured buy fee is deducted from the gross amount before the purchase amount is evaluated.

The current initialized buy fee is:

```text
100 bps = 1%
```

The fee is read from `GlobalStatesPDA.buy_fee_bps` and may change through protocol configuration.

### Minimum Purchase

The minimum purchase is evaluated against the buyer's **net USD-equivalent contribution after the buy fee**.

The current minimum is:

```text
MIN_BUY_AMOUNT_IN_USD_E2 = 100
```

which represents:

```text
$1.00
```

Therefore, the required gross SOL amount depends on the current SOL/USD price and configured buy fee.

### Sale Cap

The current maximum USD-equivalent sale raise is:

```text
MAX_USD_RAISE_CAP_IN_USD_E2 = 1,615,000
```

which represents:

```text
$16,150.00
```

The buyer's net USD-equivalent contribution must not exceed the remaining sale capacity.

Applications should therefore check the current sale state before constructing a purchase transaction.

### Sale Finalization

The protocol uses a finalization buffer:

```text
SALE_FINALIZATION_BUFFER_USD_E2 = 5,000
```

which represents:

```text
$50.00
```

After a successful purchase, if the remaining sale capacity falls below this buffer, the sale is finalized and becomes inactive.

The final raised amount therefore does not necessarily equal exactly `$16,150.00`.

## SOL/USD Price Feed

The `sol_usd_price_feed` account must be the configured Pyth `PriceUpdateV2` account for the RugFreePump SOL/USD feed.

The program validates:

* Full Pyth verification
* The configured SOL/USD feed ID
* A positive price
* Oracle confidence within 2% of the reported price
* A price update no older than 24 hours

### SOL/USD Feed ID

```text
0xef0d8b6fda2ceba41da15d4095d1da392a0d2f8ed0c6c7bc0f4cfac8c280b56d
```

### Devnet `PriceUpdateV2` Account

```text
7UVimffxr9ow1uXYxsr4LHAcV58mLzhmwaeKvJ1pjLiE
```

The `PriceUpdateV2` account is deployment-specific. Use the account configured for the target deployment.

## Slippage Protection

The following instruction arguments provide the state snapshot used for slippage protection:

```text
expected_total_raised_usd_e2
expected_total_sold_tokens_e6
slippage_bps
```

Read `total_raised_usd_e2` and `total_sold_tokens_e6` from the current `bonding_curve_pda` immediately before constructing the transaction and pass those values to `buy`.

`slippage_bps` specifies the maximum permitted increase in the bonding curve's average price between the supplied state snapshot and the state observed when the transaction executes.

For example:

```text
200 bps = 2%
```

If the permitted increase is exceeded, the transaction is rejected with `SlippageExceeded`.

Because another purchase can change the sale state before execution, applications should fetch these values immediately before constructing and submitting the transaction.

## Purchase Result

A successful purchase:

* Transfers the calculated tokens to the buyer's token account.
* Transfers the buyer's net SOL contribution to the bonding-curve vault.
* Transfers the configured buy fee to the platform fee vault.
* Records the buyer's net SOL contribution in `buyer_accumulation_pda`.
* Updates the bonding-curve sale state.
* Finalizes the sale when the finalization condition is reached.

All changes occur within the same Solana transaction.

The token amount is calculated by the program during execution. The internal bonding-curve calculation is not required to construct a `buy` instruction.

## Instruction Data

| Argument                        | Type  | Required | Required format                                                                                                  | Description                                                                                                                                                                                                                                        |
| ------------------------------- | ----- | -------- | ---------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
| `lamports_amount`               | `u64` | Yes      | Unsigned 64-bit integer representing the SOL amount in lamports (`1 SOL = 1,000,000,000 lamports`)               | Gross SOL amount submitted by the buyer before the buy fee. The resulting net USD-equivalent contribution must satisfy the configured minimum purchase amount and must not exceed the remaining sale cap                                            |
| `expected_total_raised_usd_e2`  | `u64` | Yes      | Unsigned integer representing a USD value with 2 decimal places (`$1.00 = 100 units`, `$123.45 = 12,345 units`)  | The expected `total_raised_usd_e2` value fetched off-chain from the bonding-curve PDA account during transaction construction. It is used as a variable to calculate the expected average bonding-curve price for slippage protection                |
| `expected_total_sold_tokens_e6` | `u64` | Yes      | Unsigned integer representing a token amount with 6 decimal places (`1 token = 1,000,000 token units`)           | The expected `total_sold_tokens_e6` value fetched off-chain from the bonding-curve PDA account during transaction construction. It is used as a variable to calculate the expected average bonding-curve price for slippage protection                |
| `slippage_bps`                  | `u16` | Yes      | Unsigned integer in basis points (`1% = 100 bps`, `100% = 10,000 bps`)                                           | The maximum permitted increase in the bonding curve's average price, measured between the expected average price calculated from the off-chain supplied values and the current average price calculated by the `buy` instruction during execution |

The `expected_total_raised_usd_e2` and `expected_total_sold_tokens_e6` values are state snapshots used by the `buy` instruction's slippage check logic. Read the current **`bonding_curve_pda`** account, derived with seeds `[b"bonding-curve", mint]`, immediately before constructing the transaction. 

These values, fetched from the bonding-curve PDA account, are already stored in their required formats and can be passed directly without unit conversion.

## TypeScript Example: Expected values fetching for slippage

```ts
import { AnchorProvider, Program } from "@coral-xyz/anchor";
import { PublicKey } from "@solana/web3.js";

// Your configured Anchor provider and RugFreePump program instance
const provider = new AnchorProvider(connection, wallet, {});
const program = new Program(IDL, provider);

const PROGRAM_ID = new PublicKey("RUGFREEPUMP_PROGRAM_ID");
const mint = new PublicKey("TOKEN_MINT_ADDRESS");

// Derive the bonding-curve PDA using the protocol's documented seeds
const [bondingCurvePda] = PublicKey.findProgramAddressSync(
  [
    Buffer.from("bonding-curve"),
    mint.toBuffer(),
  ],
  PROGRAM_ID,
);

// Fetch the current bonding-curve state
const bondingCurveAccount = await program.account.bondingCurvePda.fetch(bondingCurvePda);

// Read the state values required by the buy instruction
const expectedTotalRaisedUsdE2 = bondingCurveAccount.totalRaisedUsdE2;
const expectedTotalSoldTokensE6 = bondingCurveAccount.totalSoldTokensE6;

// Pass the fetched values to the buy instruction
const txInstruction = await program.methods
  .buy(
    lamportsAmount,
    expectedTotalRaisedUsdE2,
    expectedTotalSoldTokensE6,
    slippageBps,
  )
  .accounts({
    buyer: buyerWallet,
    mint,
    bondingCurvePda,
    // ... remaining required accounts
  })
  .instruction();
```

## Instruction Accounts

The following accounts must be supplied to `buy` in the order defined by the instruction.

| Account                          | Address / derivation                                                       | Required state / role                                                                            |
| -------------------------------- | -------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------ |
| `buyer`                          | Buyer wallet address                                                       | Must sign the transaction and pay rent for required account initialization                       |
| `mint`                           | Address of the token being purchased                                       | Must exist and match `bonding_curve_pda.token_mint_address`                                      |
| `admin_states_pda`               | RugFreePump PDA: seeds `[b"admin-states"]`                                 | Must exist                                                                                       |
| `global_states_pda`              | RugFreePump PDA: seeds `[b"global-states"]`                                | Must exist                                                                                       |
| `bonding_curve_pda`              | RugFreePump PDA: seeds `[b"bonding-curve", mint]`                          | Must exist as the data account that stores and controls the bonding-curve sale state for `mint`  |
| `bonding_curve_vault`            | RugFreePump PDA: seeds `[b"bonding-curve-vault", mint]`                    | Must exist and hold the bonding-curve sale's SOL                                                 |
| `associated_bonding_curve_ata`   | ATA for `mint`, owned by `bonding_curve_vault`                             | Must exist and hold the bonding-curve sale's tokens                                              |
| `buyer_accumulation_pda`         | RugFreePump PDA: seeds `[b"buyer-accumulation", bonding_curve_pda, buyer]` | Created with `init_if_needed` when missing; `buyer` pays the required rent                       |
| `buyer_associated_token_account` | ATA for `mint`, owned by `buyer`                                           | Created with `init_if_needed` when missing; `buyer` pays the required rent                       |
| `platform_fee_vault`             | RugFreePump PDA: seeds `[b"platform-fee-vault"]`                           | Must exist and receive the buy fee                                                               |
| `sol_usd_price_feed`             | RugFreePump uses: `7UVimffxr9ow1uXYxsr4LHAcV58mLzhmwaeKvJ1pjLiE`           | Must exist and be a valid Pyth `PriceUpdateV2` account for the required SOL/USD feed             |
| `token_program`                  | Token Program: `TokenkegQfeZyiNwAJYbNbGKPFXCWuBvf9Ss623VQ5DA`              | Required Solana program account                                                                  |
| `associated_token_program`       | Associated Token Program: `ATokenGPvbdGVxr1b2hvZbsiqW5xWH25efTNsLJA8knL`   | Required Solana program account                                                                  |
| `system_program`                 | System Program: `11111111111111111111111111111111`                         | Required Solana program account                                                                  |

## TypeScript Example: Transaction Construction

The following example derives the required accounts, reads the current `bonding_curve_pda` data account state for slippage protection, constructs the `buy` instruction, and submits it in a versioned Solana transaction.

```ts
import { Program } from "@coral-xyz/anchor";
import {
  PublicKey,
  SystemProgram,
  TransactionMessage,
  VersionedTransaction,
} from "@solana/web3.js";
import {
  ASSOCIATED_TOKEN_PROGRAM_ID,
  TOKEN_PROGRAM_ID,
  getAssociatedTokenAddressSync,
} from "@solana/spl-token";
import BN from "bn.js";

// Your configured Anchor program, connection, and wallet
const program = new Program(IDL, provider);

const PROGRAM_ID = new PublicKey("RUGFREEPUMP_PROGRAM_ID");
const mint = new PublicKey("TOKEN_MINT_ADDRESS");
const buyer = wallet.publicKey;

const lamportsAmount = new BN("1000000000"); // 1 SOL
const slippageBps = 200; // 2%

// Derive required PDAs
const [adminStatesPda] = PublicKey.findProgramAddressSync(
  [Buffer.from("admin-states")],
  PROGRAM_ID,
);

const [globalStatesPda] = PublicKey.findProgramAddressSync(
  [Buffer.from("global-states")],
  PROGRAM_ID,
);

const [bondingCurvePda] = PublicKey.findProgramAddressSync(
  [
    Buffer.from("bonding-curve"),
    mint.toBuffer(),
  ],
  PROGRAM_ID,
);

const [bondingCurveVault] = PublicKey.findProgramAddressSync(
  [
    Buffer.from("bonding-curve-vault"),
    mint.toBuffer(),
  ],
  PROGRAM_ID,
);

const [buyerAccumulationPda] = PublicKey.findProgramAddressSync(
  [
    Buffer.from("buyer-accumulation"),
    bondingCurvePda.toBuffer(),
    buyer.toBuffer(),
  ],
  PROGRAM_ID,
);

const [platformFeeVault] = PublicKey.findProgramAddressSync(
  [Buffer.from("platform-fee-vault")],
  PROGRAM_ID,
);

// Derive required ATAs
const associatedBondingCurveAta = getAssociatedTokenAddressSync(
  mint,
  bondingCurveVault,
  true,
  TOKEN_PROGRAM_ID,
  ASSOCIATED_TOKEN_PROGRAM_ID,
);

const buyerAssociatedTokenAccount = getAssociatedTokenAddressSync(
  mint,
  buyer,
);

// Fetch the current bonding-curve state
const bondingCurveAccount = await program.account.bondingCurvePda.fetch(bondingCurvePda);

// Read the state snapshot required for slippage protection
const expectedTotalRaisedUsdE2 = new BN(
  bondingCurveAccount.totalRaisedUsdE2.toString(),
);

const expectedTotalSoldTokensE6 = new BN(
  bondingCurveAccount.totalSoldTokensE6.toString(),
);

// Construct the buy instruction
const buyInstruction = await program.methods
  .buy(
    lamportsAmount,
    expectedTotalRaisedUsdE2,
    expectedTotalSoldTokensE6,
    slippageBps,
  )
  .accounts({
    buyer,
    mint,
    adminStatesPda,
    globalStatesPda,
    bondingCurvePda,
    bondingCurveVault,
    associatedBondingCurveAta,
    buyerAccumulationPda,
    buyerAssociatedTokenAccount,
    platformFeeVault,
    solUsdPriceFeed: SOL_USD_PRICE_FEED_ACCOUNT,
    tokenProgram: TOKEN_PROGRAM_ID,
    associatedTokenProgram: ASSOCIATED_TOKEN_PROGRAM_ID,
    systemProgram: SystemProgram.programId,
  })
  .instruction();

// Fetch a recent blockhash
const { blockhash } = await provider.connection.getLatestBlockhash("confirmed");

// Build the versioned transaction
const messageV0 = new TransactionMessage({
  payerKey: buyer,
  recentBlockhash: blockhash,
  instructions: [buyInstruction],
}).compileToV0Message();

const transaction = new VersionedTransaction(messageV0);

// Sign and submit
transaction.sign([wallet.payer]);

const signature = await provider.connection.sendTransaction(transaction);

console.log(signature);
```

`RUGFREEPUMP_PROGRAM_ID`, `IDL`, `provider`, `wallet`, `mint`, and `SOL_USD_PRICE_FEED_ACCOUNT` are application-specific values supplied by the integrating application.

The `buyer_accumulation_pda` and `buyer_associated_token_account` are created automatically by the `buy` instruction if they do not already exist. The buyer pays the required account rent.

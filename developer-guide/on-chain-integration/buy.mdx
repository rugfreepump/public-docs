---
title: "Buy"
description: "Integrate directly with the RugFreePump buy instruction to purchase tokens from an active bonding-curve sale."
---

The `buy` instruction purchases tokens from an active RugFreePump bonding-curve sale using SOL.

The instruction accepts a gross SOL amount, deducts the configured buy fee, converts the remaining SOL to USD-equivalent value using the validated Pyth SOL/USD price, and transfers the calculated token amount to the buyer.

## Instruction

```rust
pub fn buy(
    ctx: Context<Buy>,
    lamports_amount: u64,
    expected_total_raised_usd_e2: u64,
    expected_total_sold_tokens_e6: u64,
    slippage_bps: u16,
) -> Result<()>
```

## Arguments

| Argument                        | Type  | Unit         | Description                                                                                                     |
| :------------------------------ | :---- | :----------- | :-------------------------------------------------------------------------------------------------------------- |
| `lamports_amount`               | `u64` | Lamports     | Gross SOL amount submitted by the buyer before the buy fee. Must be greater than zero.                          |
| `expected_total_raised_usd_e2`  | `u64` | USD e2       | Expected `BondingCurvePDA.total_raised_usd_e2` immediately before execution.                                    |
| `expected_total_sold_tokens_e6` | `u64` | Token e6     | Expected `BondingCurvePDA.total_sold_tokens_e6` immediately before execution.                                   |
| `slippage_bps`                  | `u16` | Basis points | Maximum permitted increase in the bonding curve's average price between the expected state and execution state. |

The `expected_*` values are state snapshots used by the on-chain slippage check. They should be obtained from the current `BondingCurvePDA` immediately before constructing the transaction.

### Argument units

The exact integer representations used by the instruction are:

```text
1 SOL = 1,000,000,000 lamports

1 token = 1,000,000 token units

$1.00 = 100 USD e2

$123.45 = 12345 USD e2

10,000 bps = 100%
```

## Accounts

The `buy` instruction requires the following accounts:

| Account                       | Type                            | Mutable | Signer | Requirement                                                                                   |
| :---------------------------- | :------------------------------ | :------ | :----- | :-------------------------------------------------------------------------------------------- |
| `buyer`                       | `Signer`                        | Yes     | Yes    | Buyer and transaction payer.                                                                  |
| `mint`                        | `Account<Mint>`                 | Yes     | No     | Must match `bondingCurvePda.token_mint_address`.                                              |
| `adminStatesPda`              | `Account<AdminStatesPDA>`       | No      | No     | PDA derived from `["admin-states"]`.                                                          |
| `globalStatesPda`             | `Account<GlobalStatesPDA>`      | No      | No     | PDA derived from `["global-states"]`.                                                         |
| `bondingCurvePda`             | `Account<BondingCurvePDA>`      | Yes     | No     | PDA derived from `["bonding-curve", mint]`.                                                   |
| `bondingCurveVault`           | `SystemAccount`                 | Yes     | No     | PDA derived from `["bonding-curve-vault", mint]`.                                             |
| `associatedBondingCurveAta`   | `Account<TokenAccount>`         | Yes     | No     | ATA for `mint`, owned by `bondingCurveVault`. Must already exist.                             |
| `buyerAccumulationPda`        | `Account<BuyerAccumulationPDA>` | Yes     | No     | PDA derived from `["buyer-accumulation", bondingCurvePda, buyer]`. Initialized when required. |
| `buyerAssociatedTokenAccount` | `Account<TokenAccount>`         | Yes     | No     | Buyer's ATA for `mint`. Initialized when required.                                            |
| `platformFeeVault`            | `SystemAccount`                 | Yes     | No     | PDA derived from `["platform-fee-vault"]`.                                                    |
| `solUsdPriceFeed`             | `Account<PriceUpdateV2>`        | No      | No     | Required Pyth SOL/USD `PriceUpdateV2` account.                                                |
| `tokenProgram`                | `Program<Token>`                | No      | No     | SPL Token Program.                                                                            |
| `associatedTokenProgram`      | `Program<AssociatedToken>`      | No      | No     | Associated Token Program.                                                                     |
| `systemProgram`               | `Program<System>`               | No      | No     | Solana System Program.                                                                        |

For an off-chain client, `buyer` signs the transaction and pays for account initialization when `init_if_needed` creates the buyer accounts.

For CPI, the calling program must satisfy the signer and account requirements enforced by the instruction.

## PDA Derivation

All RugFreePump PDAs are derived using the RugFreePump program ID for the target deployment.

### Admin states

```text
["admin-states"]
```

### Global states

```text
["global-states"]
```

### Bonding curve

```text
["bonding-curve", mint]
```

### Bonding-curve vault

```text
["bonding-curve-vault", mint]
```

### Buyer accumulation

```text
["buyer-accumulation", bondingCurvePda, buyer]
```

The second seed component is the **bonding-curve PDA address**, not the mint address.

### Platform fee vault

```text
["platform-fee-vault"]
```

This is the actual vault receiving the buy fee.

It is distinct from the separate PDA derived using:

```text
["platform-fee"]
```

The `["platform-fee"]` PDA is not the `platformFeeVault` account required by `buy`.

### TypeScript derivation

```ts
const [adminStatesPda] =
  PublicKey.findProgramAddressSync(
    [Buffer.from("admin-states")],
    PROGRAM_ID,
  );

const [globalStatesPda] =
  PublicKey.findProgramAddressSync(
    [Buffer.from("global-states")],
    PROGRAM_ID,
  );

const [bondingCurvePda] =
  PublicKey.findProgramAddressSync(
    [
      Buffer.from("bonding-curve"),
      mint.toBuffer(),
    ],
    PROGRAM_ID,
  );

const [bondingCurveVault] =
  PublicKey.findProgramAddressSync(
    [
      Buffer.from("bonding-curve-vault"),
      mint.toBuffer(),
    ],
    PROGRAM_ID,
  );

const [buyerAccumulationPda] =
  PublicKey.findProgramAddressSync(
    [
      Buffer.from("buyer-accumulation"),
      bondingCurvePda.toBuffer(),
      buyer.toBuffer(),
    ],
    PROGRAM_ID,
  );

const [platformFeeVault] =
  PublicKey.findProgramAddressSync(
    [Buffer.from("platform-fee-vault")],
    PROGRAM_ID,
  );
```

## Associated Token Accounts

### Bonding-curve token ATA

`associatedBondingCurveAta` is the associated token account for the sale mint owned by `bondingCurveVault`.

Because `bondingCurveVault` is a PDA, the ATA must be derived with off-curve ownership enabled.

```ts
const associatedBondingCurveAta =
  getAssociatedTokenAddressSync(
    mint,
    bondingCurveVault,
    true,
    TOKEN_PROGRAM_ID,
    ASSOCIATED_TOKEN_PROGRAM_ID,
  );
```

This account must already exist before `buy` is invoked.

### Buyer token ATA

```ts
const buyerAssociatedTokenAccount =
  getAssociatedTokenAddressSync(
    mint,
    buyer,
  );
```

The `buy` instruction initializes this account when it does not already exist.

## SOL/USD Price Feed

`solUsdPriceFeed` must be the Pyth `PriceUpdateV2` account for the configured RugFreePump SOL/USD feed.

The program validates:

* Full Pyth verification.
* The configured SOL/USD feed ID.
* Positive reported price.
* Confidence no greater than 2% of the reported price.
* Price update age no greater than 24 hours.

### SOL/USD feed ID

```text
0xef0d8b6fda2ceba41da15d4095d1da392a0d2f8ed0c6c7bc0f4cfac8c280b56d
```

### Devnet PriceUpdateV2 account

```text
7UVimffxr9ow1uXYxsr4LHAcV58mLzhmwaeKvJ1pjLiE
```

For another deployment, use the `PriceUpdateV2` account configured for that deployment.

An arbitrary Pyth price account cannot be substituted.

## Sale-State Requirements

`buy` succeeds only while the bonding-curve sale is purchasable.

The program rejects the instruction when:

* Platform maintenance mode is enabled.
* The sale is inactive.
* The sale is finalized.
* The finalized sale has been canceled.
* `lamports_amount` is zero.
* The buyer has insufficient SOL.

The program also checks `sale_expires_at`.

When the current timestamp has reached the expiration time, the program marks the sale inactive and rejects the purchase.

## Buy Fee

The buy fee is read from:

```text
GlobalStatesPDA.buy_fee_bps
```

The currently initialized value is:

```text
100 bps = 1%
```

The fee is calculated from the gross submitted amount:

```text
buy_fee_lamports =
    lamports_amount × buy_fee_bps / 10,000
```

The net contribution is:

```text
net_lamports =
    lamports_amount - buy_fee_lamports
```

The net contribution is used for the bonding-curve purchase calculation.

The buy fee is not included in the buyer's recorded contribution.

For example:

```text
Gross:  1.000000000 SOL
Fee:    0.010000000 SOL
Net:    0.990000000 SOL
```

The buyer's `BuyerAccumulationPDA` is increased by `0.99 SOL`.

Integrations should read the current `buy_fee_bps` from `GlobalStatesPDA` rather than assume that the initialized value will remain unchanged.

## Minimum Purchase

The current minimum purchase constant is:

```text
MIN_BUY_AMOUNT_IN_USD_E2 = 100
```

which represents:

```text
$1.00
```

The minimum is evaluated against the **net USD-equivalent contribution after the buy fee**.

The calculation is conceptually:

```text
net_usd_e2 =
    net_lamports × sol_usd_price_e2 / 1,000,000,000
```

The resulting value must satisfy:

```text
net_usd_e2 >= 100
```

The required gross SOL amount therefore depends on the current SOL/USD price and buy fee.

## Sale Hard Cap

The current maximum USD-equivalent raise is:

```text
MAX_USD_RAISE_CAP_IN_USD_E2 = 1,615,000
```

which represents:

```text
$16,150.00
```

The net USD-equivalent contribution must fit within the remaining sale capacity.

A purchase that would exceed the hard cap is rejected.

## Sale Finalization

The finalization buffer is:

```text
SALE_FINALIZATION_BUFFER_USD_E2 = 5,000
```

which represents:

```text
$50.00
```

After a successful purchase, the program checks the remaining sale capacity.

If the remaining capacity is below the finalization buffer, the sale is finalized and marked inactive.

The final `total_raised_usd_e2` therefore does not necessarily equal exactly `$16,150.00`.

## Slippage Protection

The instruction uses the following arguments for state-based slippage protection:

```text
expected_total_raised_usd_e2
expected_total_sold_tokens_e6
slippage_bps
```

The expected values should correspond to the current bonding-curve state immediately before the transaction is constructed:

```text
expected_total_raised_usd_e2
    = BondingCurvePDA.total_raised_usd_e2

expected_total_sold_tokens_e6
    = BondingCurvePDA.total_sold_tokens_e6
```

The program compares the expected average curve price with the execution-state average curve price.

Only an increase in the average price is treated as adverse movement.

If the resulting slippage exceeds `slippage_bps`, the instruction fails with `SlippageExceeded`.

### State read

With Anchor:

```ts
const bondingCurve =
  await program.account.bondingCurvePda.fetch(
    bondingCurvePda,
  );

const expectedTotalRaisedUsdE2 =
  new BN(
    bondingCurve.totalRaisedUsdE2.toString(),
  );

const expectedTotalSoldTokensE6 =
  new BN(
    bondingCurve.totalSoldTokensE6.toString(),
  );
```

These values should be read immediately before constructing the `buy` instruction.

## Bonding-Curve Token Calculation

The token amount is calculated by the RugFreePump program from the net USD-equivalent purchase value and the current bonding-curve state.

The internal curve implementation and coefficients are not required to construct the instruction.

The resulting token amount is determined on-chain.

## Token Inventory

Before the token transfer, the program validates that `associatedBondingCurveAta`:

* Exists.
* Uses the supplied `mint`.
* Is owned by `bondingCurveVault`.
* Contains sufficient token inventory for the purchase.

## Transaction Construction

### Anchor

A direct Anchor integration can construct the instruction as follows:

```ts
const signature =
  await program.methods
    .buy(
      lamportsAmount,
      expectedTotalRaisedUsdE2,
      expectedTotalSoldTokensE6,
      slippageBps,
    )
    .accounts({
      buyer,
      mint,
      adminStatesPda,
      globalStatesPda,
      bondingCurvePda,
      bondingCurveVault,
      associatedBondingCurveAta,
      buyerAccumulationPda,
      buyerAssociatedTokenAccount,
      platformFeeVault,
      solUsdPriceFeed:
        SOL_USD_PRICE_FEED_ACCOUNT,
      tokenProgram:
        TOKEN_PROGRAM_ID,
      associatedTokenProgram:
        ASSOCIATED_TOKEN_PROGRAM_ID,
      systemProgram:
        SystemProgram.programId,
    })
    .rpc();
```

The transaction payer and signer is `buyer`.

### Constructing an instruction

The same interface can construct the instruction without submitting it:

```ts
const instruction =
  await program.methods
    .buy(
      lamportsAmount,
      expectedTotalRaisedUsdE2,
      expectedTotalSoldTokensE6,
      slippageBps,
    )
    .accounts({
      buyer,
      mint,
      adminStatesPda,
      globalStatesPda,
      bondingCurvePda,
      bondingCurveVault,
      associatedBondingCurveAta,
      buyerAccumulationPda,
      buyerAssociatedTokenAccount,
      platformFeeVault,
      solUsdPriceFeed:
        SOL_USD_PRICE_FEED_ACCOUNT,
      tokenProgram:
        TOKEN_PROGRAM_ID,
      associatedTokenProgram:
        ASSOCIATED_TOKEN_PROGRAM_ID,
      systemProgram:
        SystemProgram.programId,
    })
    .instruction();
```

The resulting instruction can be included in a transaction constructed by the integrating application.

## Buyer Accounting

`BuyerAccumulationPDA` contains:

```rust
pub struct BuyerAccumulationPDA {
    pub total_lamports_contributed: u64,
}
```

The value represents the buyer's cumulative net SOL contribution after buy fees.

For example:

```text
Gross purchase: 1.000000000 SOL
Buy fee:        0.010000000 SOL
Recorded:       0.990000000 SOL
```

The account is initialized by `buy` when required using `init_if_needed`, with the buyer as payer.

## Transaction State Changes

A successful purchase performs the following protocol state changes:

1. Transfers the calculated token amount from the bonding-curve token ATA to the buyer token ATA.
2. Transfers the net SOL contribution from the buyer to the bonding-curve vault.
3. Transfers the buy fee from the buyer to the platform fee vault.
4. Updates bonding-curve accounting.
5. Updates buyer contribution accounting.
6. Finalizes the sale when the finalization condition is reached.

These operations occur within the same Solana transaction.

## Events

A successful purchase emits `BuyCompleted`:

```rust
pub struct BuyCompleted {
    pub token_mint_address: Pubkey,
    pub token_buyer_address: Pubkey,
    pub buy_amount_in_lamports: u64,
    pub buy_amount_in_usd_e2: u64,

    pub buy_fee_in_lamports: u64,
    pub last_sol_usd_price_e2: u64,
    pub total_sold_tokens_e6: u64,
    pub total_raised_lamports: u64,
    pub total_raised_usd_e2: u64,
    pub total_buy_count: u64,
    pub sale_finalized_at: i64,
    pub is_sale_active: bool,

```

```rust

    pub count_of_collected_buy_fee_in_lamports: u64,
    pub total_raised_lamports: u64,
    pub total_buy_count: u64,

```

Protocol-specific failures include:

```text
PlatformMaintenanceEnabled
SaleNotActive
SaleFinalized
FinalizedSaleAlreadyCanceled
InvalidBuyAmount
InsufficientWalletBalance
IntegerOverflow

UnverifiedPythPriceFeed

BuyAmountTooSmall

```

Account constraints can additionally reject the instruction when supplied accounts do not satisfy the required mint, PDA, ownership, or program relationships.

## CPI

`buy` is a public Anchor instruction and can be invoked by another Solana program through CPI.

The CPI caller must provide the same account structure and satisfy the same signer, state, oracle, amount, and slippage requirements enforced by the instruction.

RugFreePump does not currently provide a maintained CPI wrapper or Rust integration crate.

A dedicated CPI wrapper and Rust crate are planned as future developer tooling.

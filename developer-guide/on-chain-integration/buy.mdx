---
title: "Buy"
description: "Integrate with the protocol's buy instruction to purchase tokens from an active bonding-curve sale."
---

The `buy` instruction purchases tokens from an active RugFreePump bonding-curve sale using SOL.

The instruction accepts a gross SOL amount, deducts the configured protocol fee, denominates the remaining SOL contribution in USD-equivalent terms using a validated Pyth SOL/USD price feed, calculates the corresponding token amount using the bonding curve pricing model, and transfers the tokens to the buyer.

### Instruction Signature

```rust
pub fn buy(
    ctx: Context<Buy>,
    lamports_amount: u64,
    expected_total_raised_usd_e2: u64,
    expected_total_sold_tokens_e6: u64,
    slippage_bps: u16,
) -> Result<()>
```

## Instruction Data

| Argument                        | Type  | Required | Required format                                                                                                     | Description                                                                                                                                                                                                                       |
| ------------------------------- | ----- | -------- | ------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `lamports_amount`               | `u64` | Yes      | Unsigned 64-bit integer representing the SOL amount in lamports (`1 SOL = 1,000,000,000 lamports`).                 | Gross SOL amount submitted by the buyer before the buy fee. The resulting net USD-equivalent contribution must satisfy the configured minimum purchase amount and must not exceed the remaining sale cap.                   |
| `expected_total_raised_usd_e2`  | `u64` | Yes      | Unsigned integer representing a USD value with 2 decimal places (`$1.00 = 100 units`, `$123.45 = 12,345 units`).    | The expected `total_raised_usd_e2` value fetched off-chain from the bonding-curve PDA account by the buyer while constructing the transaction. Used as a variable in the calculation of the expected average bonding-curve price for slippage protection. |
| `expected_total_sold_tokens_e6` | `u64` | Yes      | Unsigned integer representing a token amount with 6 decimal places (`1 token = 1,000,000 token units`).             | The expected total_sold_tokens_e6 value fetched off-chain from the bonding-curve PDA account by the buyer while constructing the transaction. Used as a variable in the calculation of the expected average bonding-curve price for slippage protection. |
| `slippage_bps`                  | `u16` | Yes      | Unsigned integer in basis points (`1% = 100 bps`, `100% = 10,000 bps`).                                             | Maximum permitted increase in the bonding curve's average token price between the expected state fetched off-chain and the current state read by the `buy` instruction during execution.                                                           |

The `expected_total_raised_usd_e2` and `expected_total_sold_tokens_e6` values are state snapshots used by the buy instruction's slippage check logic. Read the current **`bonding_curve_pda`** account, derived with seeds `[b"bonding-curve", mint]`, immediately before constructing the transaction.

### TypeScript Example

```ts
import { AnchorProvider, Program } from "@coral-xyz/anchor";
import { PublicKey } from "@solana/web3.js";

// Your configured Anchor provider and RugFreePump program instance
const provider = new AnchorProvider(connection, wallet, {});
const program = new Program(IDL, provider);

const PROGRAM_ID = new PublicKey("RUGFREEPUMP_PROGRAM_ID");
const mint = new PublicKey("TOKEN_MINT_ADDRESS");

// Derive the bonding-curve PDA using the protocol's documented seeds
const [bondingCurvePda] = PublicKey.findProgramAddressSync(
  [
    Buffer.from("bonding-curve"),
    mint.toBuffer(),
  ],
  PROGRAM_ID,
);

// Fetch the current bonding-curve state
const bondingCurveAccount = await program.account.bondingCurvePda.fetch(bondingCurvePda);

// Read the state values required by the buy instruction
const expectedTotalRaisedUsdE2 = bondingCurveAccount.totalRaisedUsdE2;
const expectedTotalSoldTokensE6 = bondingCurveAccount.totalSoldTokensE6;

// Pass the fetched values to the buy instruction
const txInstruction = await program.methods
  .buy(
    lamportsAmount,
    expectedTotalRaisedUsdE2,
    expectedTotalSoldTokensE6,
    slippageBps,
  )
  .accounts({
    buyer: buyerWallet,
    mint,
    bondingCurvePda,
    // ... remaining required accounts
  })
  .instruction();
```
## Instruction Accounts

The following accounts must be supplied to `buy` in the order defined by the instruction.

| Account                          | Address / derivation                                                        | Initialization / requirement                                                |
| -------------------------------- | --------------------------------------------------------------------------- | --------------------------------------------------------------------------- |
| `buyer`                          | Buyer's wallet address.                                                     | Transaction signer and payer.                                               |
| `mint`                           | Address of the token being purchased.                                       | Must match `bonding_curve_pda.token_mint_address`.                          |
| `admin_states_pda`               | RugFreePump PDA: seeds `[b"admin-states"]`.                                 | The account must exist.                                                     |
| `global_states_pda`              | RugFreePump PDA: seeds `[b"global-states"]`.                                | The account must exist.                                                     |
| `bonding_curve_pda`              | RugFreePump PDA: seeds `[b"bonding-curve", mint]`.                          | The account must exist for the sale.                                        |
| `bonding_curve_vault`            | RugFreePump PDA: seeds `[b"bonding-curve-vault", mint]`.                    | The account must exist. Holds the sale's SOL.                               |
| `associated_bonding_curve_ata`   | ATA for `mint`, owned by `bonding_curve_vault`.                             | The account must exist and contain sufficient tokens for the purchase.      |
| `buyer_accumulation_pda`         | RugFreePump PDA: seeds `[b"buyer-accumulation", bonding_curve_pda, buyer]`. | Created with `init_if_needed` when missing; `buyer` pays the required rent. |
| `buyer_associated_token_account` | ATA for `mint`, owned by `buyer`.                                           | Created with `init_if_needed` when missing; `buyer` pays the required rent. |
| `platform_fee_vault`             | RugFreePump PDA: seeds `[b"platform-fee-vault"]`.                           | The account must exist. Receives the buy fee.                               |
| `sol_usd_price_feed`             | Configured Pyth `PriceUpdateV2` account for the RugFreePump SOL/USD feed.   | Must contain a valid, accepted price update.                                |
| `token_program`                  | SPL Token Program: `TokenkegQfeZyiNwAJbNbGKPFXCWuBvf9Ss623VQ5DA`.           | Required program account.                                                   |
| `associated_token_program`       | Associated Token Program: `ATokenGPvbdGVxr1b2hvZbsiqW5xWH25efTNsLJA8knL`.   | Required program account.                                                   |
| `system_program`                 | Solana System Program: `11111111111111111111111111111111`.                  | Required program account.                                                   |

`buyer_accumulation_pda` and `buyer_associated_token_account` are the only accounts created by `buy` when missing.

Exact account rent is determined by the target Solana cluster at transaction execution time.

### Bonding-curve token ATA

The bonding-curve token ATA is owned by the `bonding_curve_vault` PDA, not by the `bonding_curve_pda`.

Derive it with the bonding-curve vault as the owner and allow off-curve ownership:

```ts
const associatedBondingCurveAta =
  getAssociatedTokenAddressSync(
    mint,
    bondingCurveVault,
    true,
    TOKEN_PROGRAM_ID,
    ASSOCIATED_TOKEN_PROGRAM_ID,
  );
```

This account must exist before calling `buy`.

### Buyer token ATA

The buyer's token ATA is derived normally:

```ts
const buyerAssociatedTokenAccount =
  getAssociatedTokenAddressSync(
    mint,
    buyer,
  );
```

`buy` creates it automatically when it does not already exist.

## PDA Derivation

All RugFreePump PDAs are derived with the RugFreePump program ID for the target deployment.

```ts
const [adminStatesPda] =
  PublicKey.findProgramAddressSync(
    [Buffer.from("admin-states")],
    PROGRAM_ID,
  );

const [globalStatesPda] =
  PublicKey.findProgramAddressSync(
    [Buffer.from("global-states")],
    PROGRAM_ID,
  );

const [bondingCurvePda] =
  PublicKey.findProgramAddressSync(
    [
      Buffer.from("bonding-curve"),
      mint.toBuffer(),
    ],
    PROGRAM_ID,
  );

const [bondingCurveVault] =
  PublicKey.findProgramAddressSync(
    [
      Buffer.from("bonding-curve-vault"),
      mint.toBuffer(),
    ],
    PROGRAM_ID,
  );

const [buyerAccumulationPda] =
  PublicKey.findProgramAddressSync(
    [
      Buffer.from("buyer-accumulation"),
      bondingCurvePda.toBuffer(),
      buyer.toBuffer(),
    ],
    PROGRAM_ID,
  );

const [platformFeeVault] =
  PublicKey.findProgramAddressSync(
    [Buffer.from("platform-fee-vault")],
    PROGRAM_ID,
  );
```

The `buyer_accumulation_pda` uses the **bonding-curve PDA address** as its second seed:

```text
["buyer-accumulation", bondingCurvePda, buyer]
```

It does not use the mint directly.

### Platform fee vault

The account required by `buy` is derived from:

```text
["platform-fee-vault"]
```

This is distinct from the separate PDA derived from:

```text
["platform-fee"]
```

The `["platform-fee"]` PDA is not the fee vault supplied to `buy`.

## SOL/USD Price Feed

The `sol_usd_price_feed` account must be a Pyth `PriceUpdateV2` account containing the configured RugFreePump SOL/USD feed.

The program requires:

* Full Pyth verification.
* The configured RugFreePump SOL/USD feed ID.
* A positive price.
* Confidence no greater than 2% of the reported price.
* A price update no older than 24 hours.

### SOL/USD feed ID

```text
0xef0d8b6fda2ceba41da15d4095d1da392a0d2f8ed0c6c7bc0f4cfac8c280b56d
```

### Devnet `PriceUpdateV2` account

```text
7UVimffxr9ow1uXYxsr4LHAcV58mLzhmwaeKvJ1pjLiE
```

The `PriceUpdateV2` account is deployment-specific. Use the account configured for the target deployment.

An arbitrary Pyth price account cannot be substituted.

## Purchase Requirements

The sale must satisfy all of the following conditions when the transaction executes:

* Platform maintenance mode is disabled.
* The sale is active.
* The sale is not finalized.
* The finalized sale has not been canceled.
* `lamports_amount` is greater than zero.
* The buyer has at least `lamports_amount` available.
* The supplied slippage parameters pass the on-chain slippage check.
* The Pyth SOL/USD price passes all oracle validation.
* The resulting net USD-equivalent contribution is at least the minimum purchase amount.
* The purchase does not exceed the remaining sale cap.
* The bonding-curve token ATA contains enough tokens.

If the current time has reached `sale_expires_at`, the program marks the sale inactive and the purchase is rejected.

## Buy Fee

The current buy fee is read from:

```text
GlobalStatesPDA.buy_fee_bps
```

The currently initialized value is:

```text
100 bps = 1%
```

The fee is calculated from the gross `lamports_amount`:

```text
buy_fee_lamports =
    lamports_amount × buy_fee_bps / 10,000
```

The remaining amount is the buyer's net contribution:

```text
net_lamports =
    lamports_amount - buy_fee_lamports
```

The net contribution is used for the bonding-curve purchase calculation.

The fee is not included in the buyer's recorded contribution.

For example:

```text
Gross:  1.000000000 SOL
Fee:    0.010000000 SOL
Net:    0.990000000 SOL
```

Read `buy_fee_bps` from `GlobalStatesPDA` rather than assuming the currently initialized value will remain unchanged.

## Minimum Purchase

The current minimum purchase is:

```text
MIN_BUY_AMOUNT_IN_USD_E2 = 100
```

which represents:

```text
$1.00
```

The minimum is checked against the **net USD-equivalent contribution after the buy fee**:

```text
net_usd_e2 =
    net_lamports × sol_usd_price_e2 / 1,000,000,000
```

The result must satisfy:

```text
net_usd_e2 >= 100
```

Therefore, the required gross SOL amount depends on the current SOL/USD price and configured buy fee.

## Sale Hard Cap

The current maximum USD-equivalent raise is:

```text
MAX_USD_RAISE_CAP_IN_USD_E2 = 1,615,000
```

which represents:

```text
$16,150.00
```

The net USD-equivalent contribution must fit within the remaining sale capacity.

A purchase that exceeds the remaining capacity is rejected.

## Sale Finalization

The finalization buffer is:

```text
SALE_FINALIZATION_BUFFER_USD_E2 = 5,000
```

which represents:

```text
$50.00
```

After a successful purchase, the program checks the remaining sale capacity.

If the remaining capacity is below the finalization buffer:

* `is_sale_finalized` is set to `true`.
* `is_sale_active` is set to `false`.
* `sale_finalized_at` is recorded.

The final `total_raised_usd_e2` therefore does not necessarily equal exactly `$16,150.00`.

## Slippage Protection

The following arguments provide the state snapshot used by the slippage check:

```text
expected_total_raised_usd_e2
expected_total_sold_tokens_e6
slippage_bps
```

Read the current bonding-curve state immediately before constructing the transaction:

```ts
const bondingCurve =
  await program.account.bondingCurvePda.fetch(
    bondingCurvePda,
  );

const expectedTotalRaisedUsdE2 =
  new BN(
    bondingCurve.totalRaisedUsdE2.toString(),
  );

const expectedTotalSoldTokensE6 =
  new BN(
    bondingCurve.totalSoldTokensE6.toString(),
  );
```

The program calculates an expected average curve price from the supplied state values and compares it with the current average price in the bonding-curve account.

Only an increase in the average price is treated as adverse movement.

The transaction fails with `SlippageExceeded` when the calculated increase exceeds `slippage_bps`.

Because another purchase can change the bonding-curve state between the state read and transaction execution, the values should be read immediately before constructing and submitting the transaction.

## Bonding-Curve Token Calculation

The program calculates the token amount on-chain from:

* The net USD-equivalent contribution after the buy fee.
* The current `total_raised_usd_e2` value.

The internal bonding-curve coefficients and calculation implementation are not required to construct the `buy` instruction.

The resulting token amount is determined on-chain.

## Transaction Construction

### Anchor

A direct Anchor integration can construct and submit the instruction as follows:

```ts
const signature =
  await program.methods
    .buy(
      lamportsAmount,
      expectedTotalRaisedUsdE2,
      expectedTotalSoldTokensE6,
      slippageBps,
    )
    .accounts({
      buyer,
      mint,
      adminStatesPda,
      globalStatesPda,
      bondingCurvePda,
      bondingCurveVault,
      associatedBondingCurveAta,
      buyerAccumulationPda,
      buyerAssociatedTokenAccount,
      platformFeeVault,
      solUsdPriceFeed: SOL_USD_PRICE_FEED_ACCOUNT,
      tokenProgram: TOKEN_PROGRAM_ID,
      associatedTokenProgram: ASSOCIATED_TOKEN_PROGRAM_ID,
      systemProgram: SystemProgram.programId,
    })
    .rpc();
```

The `buyer` is the transaction signer and payer.

### Constructing the instruction without submitting it

The same interface can construct the instruction without sending it:

```ts
const instruction =
  await program.methods
    .buy(
      lamportsAmount,
      expectedTotalRaisedUsdE2,
      expectedTotalSoldTokensE6,
      slippageBps,
    )
    .accounts({
      buyer,
      mint,
      adminStatesPda,
      globalStatesPda,
      bondingCurvePda,
      bondingCurveVault,
      associatedBondingCurveAta,
      buyerAccumulationPda,
      buyerAssociatedTokenAccount,
      platformFeeVault,
      solUsdPriceFeed: SOL_USD_PRICE_FEED_ACCOUNT,
      tokenProgram: TOKEN_PROGRAM_ID,
      associatedTokenProgram: ASSOCIATED_TOKEN_PROGRAM_ID,
      systemProgram: SystemProgram.programId,
    })
    .instruction();
```

The resulting instruction can be added to a transaction constructed by the integrating application or used by an on-chain program for CPI.

## Buyer Accounting

`buyer_accumulation_pda` records the buyer's cumulative **net SOL contribution after buy fees**.

The stored field is:

```rust
pub total_lamports_contributed: u64
```

For example:

```text
Gross purchase: 1.000000000 SOL
Buy fee:        0.010000000 SOL
Recorded:       0.990000000 SOL
```

The account is initialized by `buy` when required.

## Transaction State Changes

A successful purchase:

1. Transfers the calculated token amount from `associated_bonding_curve_ata` to the buyer's token ATA.
2. Transfers the net SOL contribution from `buyer` to `bonding_curve_vault`.
3. Transfers the buy fee from `buyer` to `platform_fee_vault`.
4. Updates bonding-curve accounting.
5. Updates the buyer's accumulated contribution.
6. Finalizes the sale when the finalization condition is reached.

These operations occur within the same Solana transaction.

## Events

A successful purchase emits `BuyCompleted`:

```rust
pub struct BuyCompleted {
    pub token_mint_address: Pubkey,
    pub token_buyer_address: Pubkey,
    pub buy_amount_in_lamports: u64,
    pub buy_amount_in_usd_e2: u64,
    pub buy_amount_in_tokens_e6: u64,
    pub buy_fee_in_lamports: u64,
    pub last_sol_usd_price_e2: u64,
    pub total_sold_tokens_e6: u64,
    pub total_raised_lamports: u64,
    pub total_raised_usd_e2: u64,
    pub total_buy_count: u64,
    pub sale_finalized_at: i64,
    pub is_sale_active: bool,
    pub is_sale_finalized: bool,

```

If the purchase finalizes the sale, `BondingCurveSaleFinalized` is also emitted:

```rust

    pub total_raised_lamports: u64,
    pub total_buy_count: u64,

```

## Failure Conditions

Important protocol-specific errors include:

```text
PlatformMaintenanceEnabled
SaleNotActive
SaleFinalized
FinalizedSaleAlreadyCanceled
InvalidBuyAmount
InsufficientWalletBalance
IntegerOverflow
SlippageExceeded
UnverifiedPythPriceFeed
InvalidSOLUSDFeedId
OutdatedPriceFeed
InvalidPriceFeed
UnreliablePriceFeed
InvalidBuyFeeRange
BuyAmountTooSmall
SaleCapHasExceeded
ZeroBuyTokenAmount
InsufficientTokenBalance
InvalidBondingCurveVault
InvalidPlatformFeeVault
```

Account constraints can additionally reject the instruction when supplied accounts do not satisfy the required mint, PDA, ownership, signer, or program relationships.

`buy` is a public Anchor instruction and can also be invoked through CPI using the same instruction arguments and account requirements.

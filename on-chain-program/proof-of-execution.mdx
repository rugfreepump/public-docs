This page provides a transparent execution record of the program from compilation through deployment and initialization, followed by the execution of every public instruction exposed by the RugFreePump on-chain program.

## The RugFreePump On-Chain Program

The RugFreePump program contains the core on-chain logic responsible for creating and operating algorithmic bonding-curve sales.

The deployed program contains **53 total instructions**:

* **49 administrative instructions** — restricted to authorized platform administration.
* **4 public instructions** — user-facing entrypoints invoked through the RugFreePump dApp.

The four public instructions define the core bonding-curve sale lifecycle on-chain:

| Instruction         | Purpose                                                                               |
| ------------------- | ------------------------------------------------------------------------------------- |
| `create_pool`       | Creates a new SPL token mint and establishes its associated bonding-curve sale pool.  |
| `buy`               | Allows users to purchase tokens from an active bonding-curve sale pool using SOL.     |
| `withdraw`          | Returns the buyer's contributed SOL when a bonding-curve sale expires or is canceled. |
| `migrate_liquidity` | Migrates the completed bonding-curve sale liquidity into a Raydium CPMM pool.         |

The restricted administrative instructions are separate from the public user execution flow demonstrated below.

### 3. Withdraw

The `withdraw` instruction handles the return of the buyer's contributed SOL when a bonding-curve sale expires or is canceled.

The associated tokens from that contribution are burned if they remain in the contributor's wallet. Transferring those tokens to another wallet does not prevent the SOL withdrawal, because the contribution's on-chain state determines eligibility and the withdrawal amount.

## Verify the Program on Solana

RugFreePump is designed so that its core user-facing operations are executed directly by the on-chain program rather than being represented solely by dApp-level state.

The program has a public Program ID, and the transactions generated by its public instructions are recorded directly on Solana and remain independently inspectable.

Every public operation demonstrated on this page includes its corresponding transaction signature, allowing users to inspect the actual on-chain execution independently of the RugFreePump dApp.

Users can verify the Program ID, inspect the transaction details, and review the resulting on-chain state directly through Solscan.

This provides a clear separation between the dApp interface and the underlying execution layer: the dApp provides the interface for constructing and submitting transactions, while Solana records the resulting execution as a publicly inspectable ledger record.

### About the Verification Environment

The demonstrations on this page were performed exclusively on **Solana Devnet**.

Devnet provides a public Solana environment for demonstrating the deployed program and its public operations without requiring real funds.

The Program ID and transaction signatures shown above correspond to publicly accessible Devnet records and can be independently inspected through Solscan.

This page demonstrates the deployment, initialization, and execution of the RugFreePump on-chain program. It is not an independent security audit, formal verification, or guarantee that the program is free from vulnerabilities.

For production mainnet interactions, users should verify that the Program ID presented by the official RugFreePump dApp matches the officially published production Program ID and review the transaction details presented by their wallet before approving a transaction.

The objective is straightforward: make the on-chain layer of RugFreePump transparent and independently inspectable, giving users the ability to verify the program identity and actual transaction execution rather than relying solely on dApp-level claims.

# Bonding-Curve Sale Risks

RugFreePump bonding-curve sales are programmable on-chain markets where the token amount received from a purchase depends on the sale's current state.

The bonding curve provides deterministic protocol pricing for purchases, but it does not guarantee profitability, liquidity, or future token value.

## Price movement

The effective purchase price changes as the sale progresses.

Earlier and later purchases can therefore receive different token quantities for the same amount of SOL.

A purchase price determined by the bonding curve should not be interpreted as a guaranteed market value.

## Sale progression

The number of tokens and amount of SOL raised are recorded in the sale's on-chain state.

As purchases occur:

- The sale progresses
- The bonding-curve position changes
- The purchase calculation changes
- The remaining sale capacity decreases

Users should review the current sale state before submitting a transaction.

## Minimum purchase amount

The current protocol configuration requires a minimum USD-equivalent purchase amount.

The current minimum is $120 USD equivalent.

This threshold is part of the on-chain purchase rules and can cause a transaction to fail when the net purchase amount is below the required minimum.

## Maximum sale raise

The bonding-curve sale has a protocol-level maximum USD raise.

The current configuration uses approximately $16,150 USD as the maximum raise.

The sale can finalize before the nominal maximum is reached because the protocol uses a finalization buffer.

The current buffer is approximately $16,100 USD.

These values are protocol configuration, not guarantees about how much a particular sale will raise.

## Creator's initial purchase

Creating a RugFreePump sale includes an initial creator purchase.

The creator supplies the initial SOL amount as part of the pool-creation operation, and the program processes that purchase through the creator-buy path.

The initial purchase is subject to the applicable purchase rules, including:

- Purchase fee
- Minimum purchase requirement
- Sale cap
- Bonding-curve pricing
- Token allocation
- Creator contribution accounting

Creators should therefore understand that creating a sale is not only a metadata operation; it also includes an initial bonding-curve purchase.

## Sale expiration

A sale has an automatic expiration mechanism based on the configured sale duration.

Once an active sale reaches its expiration time, the withdrawal path can transition the sale into an expired state.

An expired sale is no longer available for normal purchases.

## Sale cancellation

Finalized sales can also enter a dedicated emergency cancellation state through the authorized administrative path when the required emergency conditions are met.

This is different from ordinary expiration.

The cancellation mechanism exists as an exceptional protocol path and can affect how finalized-sale funds are handled.

## Withdrawal after expiration or cancellation

Eligible contributors can withdraw their recorded contribution when the program's withdrawal conditions are satisfied.

The withdrawal amount is based on the contributor's recorded on-chain contribution, subject to the program's available-vault-balance protection.

Users should not interpret the existence of a withdrawal instruction as an unconditional guarantee that every possible cost associated with participation will be recovered.

## Token handling during withdrawal

The withdrawal mechanism has an important token-handling behavior.

When the contributor's token account contains tokens at the time of withdrawal, the program can burn the current balance of that account as part of the withdrawal process.

The program does not determine the origin of each token in that account.

As a result, users should be careful when transferring RugFreePump sale tokens between wallets before using a withdrawal path.

Tokens transferred to another wallet are not automatically tracked by the original contribution record.

## Fees and sale outcomes

A sale can expire or be canceled after fees have already been charged.

Withdrawal of eligible contributed SOL does not automatically mean that previously charged protocol or network fees are returned.

Users should evaluate the total cost of participating in a sale rather than assuming that an eventual withdrawal reverses every prior expense.

See [Fees and Refund Risks](/security-and-risk/fees-and-refund-risks) for details.

## Slippage risk

The purchase instruction includes user-configured slippage protection.

This protects the transaction against excessive change in the sale state between expected and executed conditions.

It does not protect against:

- Future price changes
- Market losses
- Post-migration price movement
- Low external liquidity
- Changes in demand
- Token-specific risks

## Market risk

A bonding curve determines the protocol execution price.

It does not create guaranteed external market liquidity.

After a token reaches its migration stage, its price may change substantially depending on the resulting liquidity and external market activity.

Users can lose some or all of the value of their purchase.

## Creator and token risk

RugFreePump provides the infrastructure for a token sale but does not guarantee the quality, legitimacy, utility, or future development of any individual token project.

Creators may control significant amounts of their token supply, including tokens received through the initial creator purchase.

Users should independently evaluate the creator, token, project claims, and associated risks.

## No guaranteed return

Participation in a bonding-curve sale is not a guaranteed-return product.

A token can:

- Decline in value
- Become illiquid
- Fail to attract demand
- Lose most or all of its market value
- Experience extreme volatility

Users should only participate with assets they can afford to lose.

## Transaction execution risk

Purchases are subject to Solana transaction execution.

Transactions can fail because of:

- Insufficient balance
- Slippage conditions
- Oracle conditions
- Sale state changes
- Account errors
- Network conditions
- Other program requirements

Users should confirm the final transaction status after submission.

## User responsibility

Before purchasing, users should review:

- The token mint address
- Creator information
- Current sale progress
- Current token price
- Expected token amount
- Slippage tolerance
- Wallet balance
- Applicable fees
- Sale expiration state

The dApp provides an interface to the protocol, but users remain responsible for the transactions they authorize.

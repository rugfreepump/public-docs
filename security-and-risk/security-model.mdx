# Security Model

RugFreePump is a Solana-based token launch platform built around on-chain bonding-curve sales. Security depends on multiple layers working together: the RugFreePump on-chain program, Solana, oracle infrastructure, external protocol integrations, platform infrastructure, and the wallets and users interacting with the system.

This page explains those layers, what each one controls, and where trust and operational risk remain.

<Note>
Security information describes the current RugFreePump architecture and operational model. It is not a guarantee that losses are impossible or that every component is free of vulnerabilities.
</Note>

## Security boundaries

RugFreePump should be understood as several distinct security domains.

### RugFreePump on-chain program

The on-chain program is responsible for enforcing the core bonding-curve sale lifecycle on Solana.

This includes:

- Creating token mints and bonding-curve sale state
- Maintaining sale state and contribution accounting
- Calculating bonding-curve purchases
- Applying configured protocol fees
- Enforcing purchase limits and sale conditions
- Processing eligible withdrawals
- Handling sale expiration and cancellation states
- Controlling liquidity migration conditions
- Interacting with external on-chain programs where required

The program is the authoritative execution layer for these operations.

### Solana

Solana provides the blockchain execution environment in which RugFreePump transactions execute.

Once a transaction is submitted, the resulting state changes are determined by Solana transaction execution and the accounts and programs involved.

RugFreePump does not control the Solana network, transaction ordering, network availability, validator behavior, or network fees.

### Oracle infrastructure

Bonding-curve operations that require SOL/USD conversion depend on an external price feed.

The current implementation uses Pyth price data and validates the supplied price before using it.

The oracle is therefore an external dependency and introduces risks such as stale data, unavailable data, unexpected market conditions, or incorrect external pricing.

### External liquidity infrastructure

Completed sales can interact with Raydium CPMM infrastructure during liquidity migration.

This introduces an additional trust and execution boundary because Raydium is an external on-chain protocol that RugFreePump does not control.

### Platform infrastructure

The RugFreePump website, APIs, indexing services, databases, real-time infrastructure, metadata infrastructure, RPC providers, and other off-chain services support the user experience.

These services can affect availability and what information is displayed without changing the underlying authority of the Solana program.

A platform outage or indexing delay does not necessarily mean that the underlying on-chain state has changed.

## Current administrative trust model

RugFreePump is currently operated by a single authorized operator.

At the current stage of the project:

- The on-chain program is upgradeable.
- The founder/developer currently controls the program upgrade authority.
- Administrative and configuration authorities are currently controlled by the same operator.
- Maintenance controls are currently operated by the same authority.
- Critical administrative operations do not currently require multisig approval.
- There is no independent multisig governance layer currently deployed.

This is an important trust assumption.

A compromise or unauthorized use of the relevant administrative or upgrade keys could therefore have consequences beyond a normal user wallet compromise.

RugFreePump intends to introduce stronger governance controls in the future, including multisig authorization for critical operations. The on-chain architecture has been designed with support for this direction, but future controls should not be treated as currently active.

<Warning>
Do not assume that planned multisig governance, third-party custody, or future security controls are currently protecting the protocol. The current security model is based on the authorities presently controlling the deployed system.
</Warning>

## On-chain controls

The program contains multiple state and account checks intended to constrain valid operations.

Examples include:

- PDA derivation and account validation
- Sale-state validation
- Authority checks
- Maintenance-mode checks
- Sale expiration and finalization checks
- Migration lock periods
- Reentrancy-state protection during liquidity handling
- Validation of the expected Raydium CPMM program
- Oracle verification and freshness checks
- Purchase slippage checks
- Hard contribution limits
- Token supply and mint-authority controls

These controls reduce the set of transactions that the program will accept, but they do not eliminate software, configuration, key-management, economic, or external-dependency risk.

## Token supply controls

When a token is created through RugFreePump, the current implementation creates a total supply of:

- 1,000,000,000 tokens
- 6 decimal places
- 800,000,000 tokens allocated to the bonding-curve sale
- 200,000,000 tokens allocated for liquidity

The mint authority is revoked after the initial token supply is minted.

This means the program does not retain the mint authority for later arbitrary token creation through that authority.

This is a protocol-level control, but it does not make the token itself safe or guarantee its future market value.

## Oracle controls

The current purchase path validates the Pyth price update before using it.

The implementation currently requires:

- Full Pyth verification
- The expected SOL/USD feed
- A positive price
- A price update no older than 60 seconds
- Oracle confidence within the configured 2% threshold

These checks are designed to prevent obviously stale, invalid, or insufficiently reliable price data from being used for a purchase.

They do not eliminate oracle dependency or protect users from legitimate SOL price movements.

## External protocol boundaries

Liquidity migration can interact with Raydium CPMM through an on-chain CPI.

RugFreePump validates the expected Raydium program before performing this interaction, but Raydium remains an external protocol.

Consequently, risks associated with:

- Raydium program behavior
- Raydium availability
- External pool state
- Market liquidity
- Post-migration trading
- External market conditions

remain outside RugFreePump's direct control.

## Off-chain information versus on-chain state

The RugFreePump dApp provides interfaces and information that help users understand and interact with sales.

However, the website should not be treated as the ultimate source of truth for on-chain execution.

Users can independently inspect:

- Token addresses
- Program addresses
- Transaction signatures
- Account state
- Sale state
- Liquidity migration transactions
- Other publicly available Solana data

For significant transactions, users should verify the wallet prompt and resulting transaction rather than relying only on information displayed by the website.

## Wallet security

RugFreePump does not control user private keys or seed phrases.

A compromised wallet can result in loss independently of the security of the RugFreePump program.

Users are responsible for:

- Protecting wallet credentials
- Using the official RugFreePump domain
- Verifying transaction details
- Avoiding phishing websites
- Reviewing wallet prompts
- Keeping devices and browsers secure
- Confirming token and transaction addresses when appropriate

## Security is not a single guarantee

The security of a decentralized application is the result of multiple independent components.

A correctly executing smart contract does not protect against:

- A compromised administrative key
- A compromised user wallet
- A malicious token creator
- Oracle failure
- External protocol failure
- Market losses
- Phishing
- Infrastructure compromise
- Incorrect information displayed by an off-chain service
- Loss caused by normal market activity

For this reason, users should evaluate the complete system rather than treating any single security control as a guarantee.

## Current audit status

RugFreePump has not completed a formal third-party security audit at this time.

A professional security audit is planned for a future stage of the project.

Until an audit is completed and publicly documented, users should not interpret the existence of the public on-chain program or its published source code as equivalent to an independent security audit.

## Future security improvements

RugFreePump intends to strengthen the security model over time.

Planned improvements include:

- Multisig authorization for critical operations
- Additional separation of administrative responsibilities
- Third-party security review
- Formal security audit
- Additional operational security controls

These are future improvements and are not represented as active protections today.

## Independent verification

Users and developers can independently inspect RugFreePump transactions and on-chain state through Solana-compatible explorers and tools.

For the currently documented deployment and execution records, see the [Proof of Execution](/on-chain-program/proof-of-execution) page.

Security-related claims should always be interpreted according to the actual deployed program, authorities, configuration, and transaction history at the time of use.

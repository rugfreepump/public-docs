# Oracle and Pricing Risks

RugFreePump uses SOL/USD price data when converting SOL-denominated transactions into the USD-denominated values used by the bonding-curve sale.

This introduces an external oracle dependency in addition to the normal risks associated with token pricing and market conditions.

## SOL/USD oracle dependency

The current purchase implementation uses Pyth price data.

The program does not simply accept arbitrary price information supplied by the dApp.

Before using the price, the program validates the price update and requires:

- Full verification
- The expected SOL/USD feed
- A positive price
- A price update no older than 60 seconds
- Oracle confidence within the configured 2% threshold

These checks are designed to reject stale or insufficiently reliable price updates.

They do not eliminate oracle risk.

## Stale price data

A purchase can depend on a recent SOL/USD oracle update.

If the required price data is unavailable or does not satisfy the program's freshness requirements, the transaction can fail rather than proceed using an unacceptable price.

Users may therefore encounter failed purchases during oracle outages, delayed updates, or other oracle-data problems.

## Oracle confidence

The program checks the reported confidence interval relative to the reported price.

The current implementation rejects price updates where oracle confidence exceeds 2% of the reported price.

This is a validation control rather than a guarantee that the reported market price is always correct.

## SOL price movement

SOL can move significantly while a user is preparing or submitting a transaction.

The SOL/USD value displayed before submission may therefore differ from the value used when the transaction executes.

Users should not assume that a displayed conversion remains fixed until confirmation.

## Oracle price versus token price

The SOL/USD oracle determines the SOL-to-USD conversion used by the protocol's bonding-curve calculations.

It does not determine the market value of the RugFreePump-created token.

The token's market value can change independently based on:

- Bonding-curve activity
- Buyer and seller behavior
- Sale progression
- Liquidity
- Market demand
- Post-migration trading
- External market conditions

A valid SOL/USD oracle price therefore does not imply that the token itself has a particular market value.

## Bonding-curve pricing

RugFreePump uses a polynomial bonding curve to determine the number of tokens associated with a purchase.

The purchase calculation depends on the sale's current on-chain state.

As the sale progresses, the effective purchase price can change.

This means two purchases of the same SOL amount can receive different token quantities at different points in the sale.

## Purchase slippage protection

The purchase instruction accepts an expected sale state and a user-defined slippage tolerance.

The program compares the expected state with the current state and rejects the transaction when the resulting average-price movement exceeds the user's configured tolerance.

This provides transaction-level protection against unexpected movement in the sale state between preparation and execution.

Slippage protection does not guarantee a stable token price after the transaction executes.

## Hard sale limits

The bonding-curve purchase path also enforces protocol-level limits on the sale's USD contribution amount.

The current configuration includes:

- Minimum purchase amount: $120 USD equivalent
- Maximum sale raise: approximately $16,150 USD equivalent
- Finalization buffer: approximately $16,100 USD equivalent

The exact values should be kept synchronized with the current protocol configuration.

## Oracle and transaction failure

A transaction can fail because the required oracle data is:

- Too old
- Insufficiently verified
- Outside the confidence threshold
- Invalid
- Unavailable

A failed transaction is different from a transaction that executes using an incorrect user assumption.

Users should verify the final transaction result rather than relying solely on the dApp interface.

## External dependency risk

Pyth is an external service and protocol dependency.

RugFreePump does not control:

- Pyth infrastructure
- Guardian operations
- Network-level availability
- External market data sources
- Future changes to external oracle infrastructure

Oracle-dependent functionality can therefore be affected by external events.

## User considerations

Before submitting a purchase, users should consider:

- Current SOL market conditions
- The displayed token price
- The sale's current progress
- The configured slippage tolerance
- Wallet balance
- The possibility of transaction failure
- The possibility that the token's market value can change after purchase

No oracle validation should be interpreted as a guarantee of investment value or trading outcome.

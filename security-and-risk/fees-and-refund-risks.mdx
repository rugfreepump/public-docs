# Fees and Refund Risks

RugFreePump transactions can involve several different types of costs.

A later sale expiration, cancellation, or withdrawal does not necessarily reverse costs that were already charged.

Users should distinguish between contributed SOL, protocol fees, creator incentives, external liquidity costs, and Solana network fees.

## Protocol fees

RugFreePump currently applies protocol-defined fees to applicable operations.

The current configuration includes a 1% buy fee.

The protocol also uses configured fees for other lifecycle operations, including applicable creation and completed-sale processing.

The current production configuration is intended to remain aligned with the documented RugFreePump configuration.

## Creation fee

Creating a bonding-curve sale can involve a bonding-curve escrow creation fee.

The current implementation calculates the applicable SOL amount from the configured USD-denominated fee and the current SOL/USD oracle price.

This means the SOL amount required for a USD-denominated fee can vary with the SOL/USD exchange rate.

## Buy fee

Purchases are subject to the configured buy fee.

The current buy fee is 1%.

The fee is deducted as part of the purchase calculation before the net contribution is added to the bonding-curve sale.

Users should therefore distinguish between:

- Total SOL submitted
- Applicable buy fee
- Net SOL contributing to the sale
- Resulting token amount

## Completed-sale fees

Finalized-sale processing can apply the configured completed-sale escrow fee.

The applicable amount is calculated from the finalized sale's available funds according to the program's configured rules.

This amount reduces the funds available for subsequent liquidity handling.

## DEX pool creation costs

Liquidity migration also requires the configured DEX pool creation cost.

This is separate from the bonding-curve purchase fee.

The migration process accounts for this cost when determining the amount available for external liquidity.

## Creator incentive

Where enabled by protocol configuration, an eligible creator incentive can be paid during the finalized-sale lifecycle.

The creator incentive is calculated by the program from the configured rate and applicable finalized-sale funds.

It should not be interpreted as an additional fee charged directly to the user at the time of withdrawal.

## Solana network fees

Solana transaction fees are separate from RugFreePump protocol fees.

Users may also choose to use additional priority fees depending on their wallet or transaction configuration.

These network costs are paid according to Solana transaction rules and are not RugFreePump withdrawal refunds.

## Fees are not automatically refunded

One of the most important distinctions is that withdrawing contributed SOL does not mean that all historical costs are refunded.

For example, if a sale:

- Expires
- Is canceled
- Becomes otherwise eligible for withdrawal

previously charged protocol fees and Solana network fees are not automatically reversed.

Users should therefore not assume that an expired or canceled sale results in a full recovery of every SOL spent during participation.

## Withdrawal fee

The current RugFreePump withdrawal path does not charge a separate RugFreePump withdrawal fee.

This does not eliminate the normal Solana transaction fee associated with submitting the withdrawal transaction.

## Contribution versus fees

The contributor's on-chain contribution amount is tracked separately from protocol fees.

The withdrawal calculation is based on the contributor's recorded contribution rather than a retrospective reversal of every transaction cost associated with participation.

## Available vault balance

The withdrawal implementation includes a defensive check against the SOL actually available in the bonding-curve vault while preserving the required vault balance.

As a result, documentation should not describe withdrawal as an unconditional promise to recover every historical cost or as a blanket guarantee independent of the on-chain vault state.

The authoritative amount is determined by the program at execution time.

## Failed transactions

A failed transaction should generally not be treated as a successful purchase, withdrawal, or migration.

However, Solana network transaction fees can still apply to transactions submitted to the network even when the requested instruction does not successfully complete.

Users should distinguish protocol execution from network transaction costs.

## Fee configuration risk

Protocol fees and other economic parameters are configurable by the current administrative authority.

The current operator therefore has the ability to change applicable configuration within the permissions of the deployed program.

Users should review the current published configuration before executing transactions.

## Single-operator configuration risk

Current fee and protocol configuration authority is controlled by the same single operator that controls other administrative functions.

There is currently no multisig approval requirement for these configuration changes.

This is part of the current RugFreePump trust model.

## Future governance

RugFreePump intends to introduce stronger authorization controls for critical administrative operations in the future, including multisig-based approval.

These future controls are not currently active.

## Before participating

Users should review:

- Current protocol fees
- Expected transaction costs
- Current SOL/USD conditions
- Purchase amount
- Slippage settings
- Potential priority fees
- Sale expiration conditions
- Withdrawal conditions

Users should only participate when they understand the costs that may remain non-refundable.

## No guaranteed recovery of total expenditure

A user who contributes SOL to a sale can potentially recover eligible contributed SOL through the withdrawal mechanism when the applicable conditions are met.

That does not mean the user is guaranteed to recover:

- Protocol fees
- Solana network fees
- Priority fees
- Other transaction costs
- Any external costs
- Economic losses caused by token price changes
